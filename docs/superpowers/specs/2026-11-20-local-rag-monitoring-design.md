# 本地 RAG 问答监控设计

日期：2026-11-20
状态：已确认
范围：Phase 3 的本地可观测性，不包含外部 LangSmith 账号或质量评测

## 1. 目标与边界

在不注册任何账号、不依赖外部监控平台、不引入 Docker 或新增常驻服务的前提下，为现有 LangChain RAG Web 应用增加完整问答 Trace、阶段耗时、结构化日志、只读监控页面和手动保留清理。

不重写已验收的检索、切分、模型适配、索引代际或 SSE 协议，不增加注册、角色、RBAC、登录限流或其他账号功能。不展示点赞/点踩统计；原有反馈提交和本地存储保持不变。

## 2. 数据模型

使用现有 `index.sqlite3`，通过增量迁移新增：

### `chat_runs`

一次问答一条记录，字段包括：请求 ID、会话 ID、消息 ID、原始问题、检索查询、最终 Prompt、检索文本、最终回答、索引代、状态（running/succeeded/failed/cancelled）、degraded、创建/结束时间、总耗时和已脱敏错误。

### `chat_run_events`

一次问答的多个阶段事件，字段包括：事件 ID、请求 ID、阶段名、状态、开始/结束时间、耗时、结构化详情。阶段覆盖 prepare、dense、bm25、rrf、rerank、parent_recovery、chat_stream 和 terminal。

问题、Prompt、检索文本和回答按用户确认保存在本机。密码、API Key、Cookie、CSRF Token 永不进入监控记录或 API 响应。

## 3. 采集方式

新增独立监控仓储和采集器，在 ChatService/RAGService 边界记录准备与流式生命周期，在 RetrievalService 记录检索子阶段。使用 `time.perf_counter()` 计算耗时，UTC 时间用于持久化。

采集器采用 fail-open：监控数据库或 JSONL 写入失败只记录脱敏本地告警，不得改变回答、引用、状态或 SSE 行为。终态只写一次，取消和部分回答保留 cancelled 状态。

每次请求结束追加一条完整 JSON 到 `RAG_STATE_DIR/monitoring/chat-trace.jsonl`，作为数据库之外的文本诊断副本。不引入后台上传线程。

## 4. 查询接口与页面

新增需要现有登录会话的只读接口：

- `GET /api/monitoring/summary?hours=24`：请求数、成功/失败/取消/进行中数、降级数、平均及 P95 总耗时。
- `GET /api/monitoring/runs?limit=50&status=&query=`：最近请求列表，可按状态和会话/消息/请求 ID 筛选。
- `GET /api/monitoring/runs/{run_id}`：单次问答完整内容、阶段时间线及脱敏错误。

React 增加“监控”页面，展示汇总卡片、状态筛选、最近请求和详情时间线。页面不展示点赞/点踩统计，不提供修改或删除业务数据的操作。

## 5. 保留策略

完整 Trace 默认保留 30 天，可配置。提供显式 CLI 清理命令，只删除早于截止时间的 `chat_runs`、关联 `chat_run_events` 和对应 JSONL 记录，不删除会话、消息、文档、索引、任务或反馈。

不在请求链路中自动清理，不新增常驻清理进程。清理命令输出删除数量和保留边界；重复执行应幂等。

## 6. 错误与安全

- 准备失败、模型失败、客户端取消和监控自身失败分别处理。
- 外部错误继续通过现有脱敏边界，不记录堆栈、密钥或连接凭据。
- 所有监控 API 使用现有认证；详情按 run ID 查询，单账号模型下不增加 ACL。
- JSONL 文件权限为仅运行账号可读写；目录归属部署运行账号。
- 列表默认限制 50，详情内容大小受现有问答和上下文上限约束。

## 7. 测试与验收

测试覆盖：增量迁移、成功/失败/取消生命周期、检索阶段耗时、反馈不进入汇总、监控 fail-open、认证、筛选、详情、30 天清理幂等、JSONL 内容、React 页面和 SSE 原协议回归。

服务器验收：更新代码并重启 API/Worker 后，完成一次真实问答，在监控页面看到完整 Trace；停止外部网络监控平台依赖仍可使用；未执行的项目明确标为 NOT RUN。

## 8. 文档与交付

项目根目录新增 `MONITORING_IMPLEMENTATION_GUIDE.md`。文档覆盖本次新增和修改的每一个代码文件：先说明整个代码块的功能，再逐行解释具体作用，使用通俗中文，不只解释关键片段。另包含实现流程、数据流、接口、配置、测试、部署、故障排查和保留清理。

实现完成后进行独立审查和完整回归，提交并推送至用户指定的 GitHub 仓库。若本机没有可用 GitHub 凭据，则停止并报告，不注册账号或索取密码。
