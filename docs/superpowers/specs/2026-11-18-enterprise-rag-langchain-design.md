# 企业知识库 RAG 智能问答系统设计

- 日期：2026-11-18
- 状态：架构设计已经逐节确认，等待书面评审
- 目标环境：Ubuntu 22.04 LTS x86_64
- 核心框架：LangChain + FastAPI
- 监控平台：LangSmith 免费模式

## 1. 背景与目标

构建一套可本地开发、由用户手动上传到服务器部署的企业知识库 RAG 问答系统。系统使用可重复生成的企业 Mock 知识库，支持多种文件格式、扫描 PDF OCR、父子块、混合检索、重排、流式回答、引用溯源、用户反馈、文档管理以及 LangSmith 全链路监控和效果评估。

本期容量定位为功能验证型：约 5 个并发问答、100 次问答/日，未来文档量不超过 1 万。优先保证检索质量、可观测性、可维护性和部署隔离，不引入分布式架构。

## 2. 已确认的约束和决策

| 项目 | 决策 |
|---|---|
| 交付形态 | 企业基础版 Web 应用，包含问答和知识库管理 |
| 登录与权限 | 仅一个管理员账号；不做用户管理、RBAC、ACL、SSO 和多租户 |
| Mock 内容 | 通用企业知识库，覆盖 HR、行政、IT、财务、采购、法务、产品制度 |
| 文件格式 | TXT、DOCX、文本 PDF、扫描 PDF、XLSX；Q&A 使用 XLSX，评测集使用 JSONL |
| OCR | PaddleOCR 中英文识别；默认 CPU，可在兼容性检查后切换 GPU |
| LLM | 阿里百炼 `deepseek_v4.1_flash_1017`，作为可配置模型 ID |
| Embedding | 阿里百炼 `text-embedding-v4`，默认维度 1024 |
| Rerank | 阿里百炼 `qwen3-rerank` |
| 向量数据库 | Qdrant 独立二进制进程 |
| 混合检索 | Qdrant 稠密向量 + 独立持久化中文 BM25 + RRF + Rerank |
| 切分 | 父子块；子块检索，父块提供生成上下文 |
| LangSmith 内容 | 被采集的问答 Trace 上传完整问题、回答、Prompt 和检索文本 |
| LangSmith 采样 | 验收和评测 100%；长期生产默认 20%，可配置 |
| 服务器 | Ubuntu 22.04 LTS x86_64，可直接访问外网 |
| Docker | 不使用 |
| Python 隔离 | 独立 Conda 环境 `langchain_test`，Python 3.11 |
| 部署责任 | 开发者仅本地开发和验证；用户手动上传并执行服务器部署 |

## 3. 范围与非目标

### 3.1 本期范围

- 单管理员登录和安全会话。
- Web 流式问答、多轮会话、引用展示、点赞/点踩和文字反馈。
- 文档上传、解析进度、失败原因、替换更新、重新索引和删除。
- Mock 数据生成器及生成后的完整语料。
- 父子切分、稠密检索、BM25、RRF、Rerank、父块恢复和引用生成。
- LangSmith Trace、Feedback、Datasets 和 Experiments。
- 独立评测集、质量报告、性能测试和真实 API 冒烟测试。
- 无 Docker 的 Conda + Qdrant 二进制部署方案。
- 启动、停止、健康检查、备份、恢复和部署验证脚本。

### 3.2 非目标

- 多用户、部门隔离、文档 ACL、RBAC、SSO/LDAP 和多租户。
- Kubernetes、Redis、Celery、Kafka、Milvus 集群和多节点高可用。
- 本地部署 LLM、Embedding 或 Rerank 模型。
- 旧版 DOC/XLS、图片中复杂表格的高保真结构还原和手写体 OCR。
- LangSmith 付费功能、无限 Trace 保留或完整的第三方生产告警。
- 任意未实现模型厂商或向量数据库的开箱即用支持。
- 复杂 Excel 公式执行、宏执行或通用代码执行。

## 4. 总体架构

```text
浏览器（单管理员）
        │
        ▼
FastAPI：React 静态页面、REST API、SSE 流式问答
        │
        ├── 问答服务 ── LangChain RAG Chain
        │                  ├── 多轮问题改写
        │                  ├── Qdrant 子块向量召回
        │                  ├── 中文 BM25 子块召回
        │                  ├── RRF 融合
        │                  ├── 百炼 qwen3-rerank
        │                  ├── 父块恢复、去重和引用组装
        │                  └── 百炼 LLM 流式生成
        │
        ├── 文档管理 API ── SQLite 任务队列 ── 单 ingestion Worker
        │                                      ├── 文档解析 / PaddleOCR
        │                                      ├── 父子切分
        │                                      ├── 百炼 Embedding
        │                                      └── 构建新一代索引
        │
        └── Trace、反馈及实验 ── LangSmith
```

### 4.1 组件职责

- **前端**：React + TypeScript + Ant Design；生产环境由 FastAPI 提供构建后的静态资源，服务器无需运行 Node.js。
- **API**：FastAPI 提供鉴权、文档、会话、反馈、健康检查和 SSE 问答接口。
- **RAG 服务**：LangChain 负责模型和检索器抽象以及链编排；业务服务负责版本选择、父块恢复、引用和错误策略。
- **Worker**：单进程消费 SQLite 持久化任务，执行 OCR、切分、Embedding 和索引构建，避免长任务阻塞 API。
- **SQLite**：WAL 模式，保存管理员、服务端会话、文档、任务、父块、活动索引代、聊天记录和反馈。
- **Qdrant**：保存子块稠密向量、子块文本和检索元数据。
- **BM25**：使用可持久化中文关键词索引；与 Qdrant 使用相同子块 ID。
- **文件存储**：原始文件按文档 ID 和 SHA-256 保存到项目数据目录。

## 5. Mock 知识库设计

### 5.1 数量和格式

| 数据 | 数量 | 是否入库 | 说明 |
|---|---:|---|---|
| TXT | 25 | 是 | 制度、通知、操作规范 |
| DOCX | 25 | 是 | 标题层级、段落和表格 |
| PDF | 25 | 是 | 20 个文本型、5 个扫描型 |
| XLSX | 25 | 是 | 多 Sheet、表头、合并单元格及行记录 |
| `knowledge_qa.xlsx` | 1000 条 | 是 | 独立于上述 100 个文件，每条带来源 ID |
| `evaluation.jsonl` | 100 条 | 否 | 80 条可回答、20 条不可回答 |

交付物包含 100 个普通文档、1 个知识 Q&A 文件和 1 个独立评测文件。1000 条知识 Q&A 不包含评测题，避免将评测原题直接入库造成数据泄漏。

### 5.2 内容要求

- 使用固定随机种子，可重复生成；不包含真实企业敏感信息。
- Q&A 能追溯到一个或多个来源文档及具体位置。
- 评测问题采用改写和跨句表达，不简单复制知识 Q&A 原题。
- 加入相似条款、历史版本、生效日期、易混淆术语和表格事实。
- 不可回答评测题应具有企业语境，但不能由库内事实可靠回答。
- 扫描 PDF 由已知文本生成图像型页面，以便自动验证 OCR 结果。

## 6. 文档解析与父子切分

### 6.1 解析规则

- **TXT**：检测常见编码，按标题、段落和句子解析。
- **DOCX**：保留标题层级、段落和表格行列关系。
- **文本 PDF**：按页提取文本；页码作为稳定引用元数据。
- **扫描 PDF**：仅对无有效文本层或文本层异常的页面执行 PaddleOCR；保留页码。
- **XLSX**：按 Sheet、表头和连续行组转换；保留 Sheet 名和行号；不执行公式和宏。
- **Q&A XLSX**：校验问题、答案和来源字段；问题与答案始终作为完整语义单元。

### 6.2 切分默认值

| 参数 | 默认值 |
|---|---:|
| 父块目标大小 | 1000 字符 |
| 子块目标大小 | 250 字符 |
| 子块重叠 | 50 字符 |
| 最终返回父块数 | 6 |
| 同一文档最多父块数 | 2 |
| 最大生成上下文 | 12000 字符，可配置 |

切分优先使用标题、段落、表格行组和句子边界，避免机械截断。父块用于生成，子块用于检索。Q&A 不拆散问题和答案；较短结构化内容可小于目标大小。

### 6.3 元数据

每个文档和块按需保存：

- `document_id`、`file_sha256`、`content_hash`、`version`。
- 原始文件名、媒体类型、业务领域、上传时间和解析状态。
- `parent_id`、`child_id`、`generation_id`。
- 标题路径、PDF 页码、DOCX 章节、XLSX Sheet 和行号。
- 制度版本、生效日期和是否现行版本。
- 来源位置及文本内容哈希。

文档和块 ID 必须稳定且唯一，便于引用、评测、去重和索引修复。

## 7. 索引构建和一致性

### 7.1 文档任务状态

```text
uploaded → parsing → chunking → embedding → indexing → ready
                  └──────────── 任一阶段失败 → failed
```

删除和更新也记录独立任务状态。任务持久化到 SQLite，Worker 重启后可恢复未完成任务；失败任务保留阶段、错误摘要和重试次数。

### 7.2 整代索引策略

为保证 Qdrant、BM25 和父块版本一致，采用“整代构建、增量复用、原子切换”的方式：

1. 单 Worker 获得写锁，并合并可批量处理的排队变更。
2. 在独立暂存区构建新 Qdrant Collection 和新 BM25 目录，不修改当前活动代。
3. 新增或内容变化的子块调用 Embedding；未变化子块从上一代复制向量，不重复调用 API。
4. 校验向量维度、子块 ID、父块引用、文档数量和 BM25 记录数量。
5. 校验通过后，在 SQLite 中切换唯一活动代指针。
6. 每次问答开始时读取一次活动代，并在整个请求中固定使用该代，避免一次查询混用新旧索引。
7. 旧代保留至进行中的请求结束，再由清理任务删除。
8. 构建或激活失败时继续服务上一活动代；启动时根据激活日志完成恢复或回滚。

该策略利用当前低写入频率和小规模语料换取清晰的一致性。对调用方而言，上传、修改和删除仍是增量操作，未变化内容不会重复向量化。

### 7.3 运维修复

提供一致性检查和完整重建命令，检查：

- Qdrant 与 BM25 子块 ID 差异。
- 子块引用不存在的父块。
- 向量维度与当前 Embedding 配置不一致。
- 文档状态与活动代记录不一致。
- 孤儿文件、暂存目录和过期索引代。

## 8. 问答检索与生成

### 8.1 默认参数

| 参数 | 默认值 |
|---|---:|
| 向量召回 | Top 30 |
| BM25 召回 | Top 30 |
| RRF 常数 | 60 |
| Rerank 候选数 | 30 |
| 最终父块数 | 6 |
| 多轮历史 | 最近 6 轮 |
| LLM Temperature | 0.1 |
| LLM 最大输出 | 2048 Token |

以上参数以及批大小、超时、重试和上下文预算均通过 YAML 配置。

### 8.2 查询流程

1. 验证会话并读取活动索引代。
2. 首轮直接使用原问题；多轮时调用 LLM 改写成独立检索问题，同时保留原问题用于最终回答。
3. 并行执行 Qdrant 向量召回和中文 BM25 召回。
4. 使用 RRF 融合，保留两路原始排名与分数用于分析。
5. 调用 `qwen3-rerank` 对融合候选重排。
6. 按子块和父块去重，恢复父块，控制单文档占比并合并同文档相邻内容。
7. 根据上下文预算选择父块，构造带稳定来源编号的 Prompt。
8. 调用 LLM 流式生成，返回 token、citation、done 或 error 事件。
9. 保存本地消息 ID、来源及可选的 LangSmith Run ID。反馈始终可本地提交；只有已采样的消息才能通过 Run ID 同步关联 LangSmith。

### 8.3 回答与拒答

- 默认使用中文，回答仅依据知识库内容，不主动补充未经来源支持的常识。
- 引用必须指向实际返回的父块，展示文件名、章节、页码或 Sheet/行号。
- 制度冲突时优先现行版本，并展示版本和生效日期，不静默混用历史条款。
- 候选不足、重排相关性不足或上下文无法支持答案时明确说明知识不足。
- 拒答阈值通过独立评测集校准，不使用未经验证的固定分数。
- Rerank 或单路召回降级时仍可回答，但响应和 Trace 必须标记 `degraded=true`。

## 9. Web、API 和会话

### 9.1 页面

**登录页**：仅提供单账号登录、退出和通用失败提示，不做登录限流、注册、改密或账号管理。

**问答页**：

- 新建、重命名、删除和切换会话。
- SSE 流式输出和停止生成。
- 引用片段、来源位置和原始文件下载。
- 点赞、点踩和文字反馈。
- 知识不足、检索降级和可重试错误提示。

**知识库管理页**：

- 多文件上传、文档列表、任务进度和失败原因。
- 替换更新、重新解析、重新索引和删除确认。
- 文档版本、父子块数量和来源元数据查看。

密钥、模型配置和向量库配置不通过 Web 修改或展示。

### 9.2 核心 API

```text

GET    /api/auth/me

GET    /api/documents
POST   /api/documents/upload
GET    /api/documents/{id}
```

所有业务接口要求有效会话。健康检查不泄露配置、密钥或文档内容。流式接口定义明确事件结构；客户端断开后取消不再需要的上游流式请求。

### 9.3 单管理员和会话安全

- 仅通过 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 环境变量配置一个管理员，密码以 Argon2id 哈希保存；不提供注册、改密、找回密码或账号管理工具。
- 登录、退出和 `/me` 使用服务端会话及 HttpOnly、SameSite Cookie；HTTPS 下启用 Secure。
- 修改操作仅保留会话级静态 CSRF 防护，不实现登录限流、CSRF 轮换或复杂账号策略；问答并发限制独立按 5 个请求处理。
- 会话有效期可配置，退出或过期后立即失效；不实现角色、ACL、SSO、RBAC 或多用户权限。
- 同一管理员可打开多个浏览器会话，CSRF token 在会话内保持稳定，所有会话看到相同知识库和聊天记录。
- 完整聊天历史持久化；检索默认只使用最近 6 轮，超长上下文按预算截断。

## 10. 模型、向量库与配置

### 10.1 配置边界

首期实现百炼 LLM、Embedding、Rerank 和 Qdrant 适配器，并定义清晰接口以便后续扩展。对于已实现的适配器，以下变更不需要修改业务代码：

- 模型 ID、Base URL、超时、重试、并发和批大小。
- Embedding 维度、Collection 前缀和距离度量。
- Rerank 候选数及调用参数。
- Qdrant URL、端口、数据目录和存储配置。
- 父子块、BM25、RRF、上下文和采样参数。

切换到未实现的其他厂商或向量数据库需要新增适配器，不宣称只改 YAML 即可完成。更换 Embedding 模型、维度或距离度量必须创建新索引代并完整重建，不能复用旧向量空间。

### 10.2 默认模型配置

```yaml
llm:
  provider: bailian
  model: "deepseek_v4.1_flash_1017"
  temperature: 0.1
  max_output_tokens: 2048
  timeout_seconds: 60
  max_retries: 3

embedding:
  provider: bailian
  model: "text-embedding-v4"
  dimension: 1024
  batch_size: 10
  timeout_seconds: 60
  max_retries: 3

rerank:
  provider: bailian
  model: "qwen3-rerank"
  candidate_count: 30
  timeout_seconds: 30
  max_retries: 3

vectorstore:
  provider: qdrant
  url: "http://127.0.0.1:16333"
  collection_prefix: "enterprise_rag"
  distance: "cosine"
```

模型 ID、接口路径和返回结构必须通过真实 API 冒烟测试验证。给定模型名称不可调用时明确失败并提示核对百炼控制台，不静默替换成其他模型。

### 10.3 密钥

`.env` 保存百炼 API Key、LangSmith API Key、LangSmith Endpoint/Project 和随机会话密钥，权限设置为仅所有者可读写。仓库只提供无真实值的 `.env.example`。密钥不出现在 Git、命令回显、应用日志、前端响应或 LangSmith 元数据中。

## 11. 异常处理和降级

| 故障 | 系统行为 |
|---|---|
| 百炼超时、429、5xx | 指数退避加随机抖动重试，遵守最大次数和总截止时间 |
| 百炼鉴权或参数错误 | 立即失败并给出可操作错误，不盲目重试 |
| Rerank 失败 | 使用 RRF 排序降级，响应和 Trace 标记降级 |
| 单路召回失败 | 使用另一路召回降级并记录；两路均失败则拒答 |
| LLM 流式生成失败 | 返回可重试错误，不补写虚假答案或引用 |
| Embedding 失败 | 新索引代失败，旧活动代继续服务，任务可重试 |
| OCR 或文件解析失败 | 标记具体文档和阶段，不影响其他文档任务 |
| Qdrant 不可用 | Readiness 失败；按配置只允许 BM25 降级或拒绝新问答 |
| LangSmith 不可用 | 不影响问答，记录本地错误；已采样消息的反馈先持久化后重试同步 |
| Worker 中断 | 从持久化任务和激活日志恢复，不激活半成品索引 |
| 客户端断开 | 取消可取消的上游生成，记录取消状态 |

上传校验扩展名、实际格式和大小；默认单文件最大 50 MB。文件名规范化，防止路径穿越；不执行宏、公式或文档内任何代码。日志不记录密钥和认证头。

## 12. LangSmith 监控

### 12.1 Trace 结构

```text
rag_query
├── query_rewrite
├── dense_retrieve
├── bm25_retrieve
├── rrf_fusion
├── rerank
├── parent_resolve
└── generate
```

问答 Trace 记录：

- 原始问题、改写问题、Prompt、检索文本和完整回答。
- 各阶段候选 ID、排名、分数、父块和引用。
- 应用版本、配置哈希、活动索引代、环境和模型标签。
- 各阶段延迟、重试、降级、取消和错误。
- API 返回的 Token Usage；未返回时不伪造用量。
- 已采样问答的点赞/点踩及文字反馈通过 Run ID 关联；未采样问答的反馈仅保存在本地，不伪造 LangSmith 关联。

文档处理 Trace 以任务状态、页数、块数、耗时和错误为主，避免逐页上传大体积 OCR 中间结果。开发、生产和评测使用独立 Project。

### 12.2 免费模式策略

- 验收与离线评测 100% 采样。
- 长期生产默认 20% 采样，被采集问答仍保留完整内容。
- 采样率和完整/脱敏模式均可配置，便于后续合规策略变化。
- 上线前核对账号当时的免费额度、Project/座位限制和数据保留期。
- 本地 JSON 日志独立记录请求状态、延迟、错误和降级。
- 不依赖 LangSmith 免费模式提供无限存储、完整生产告警或付费评估能力。

## 13. 效果评测与验收指标

### 13.1 方法

- 使用 100 条独立评测数据，其中 80 条可回答、20 条不可回答。
- 建立来源文档和关键证据位置标注。
- 分别评估向量、BM25、RRF 和 Rerank，验证各阶段收益。
- 使用规则检查、百炼 LLM Judge 和人工抽查，不仅依赖模型自评。
- 模型、Embedding、切分、检索参数或 Prompt 变更后运行对照实验。
- 将确认的线上 bad case 加入后续回归数据集，但不直接污染初始验收集。

### 13.2 默认验收目标

| 层面 | 指标 | 目标 |
|---|---|---:|
| 检索 | Rerank 后来源 Recall@10 | ≥ 90% |
| 排序 | MRR@10 | ≥ 0.80 |
| 引用 | 引用 ID 可解析率 | 100% |
| 引用 | 引用对答案的支持率 | ≥ 95% |
| 生成 | 忠实度通过率 | ≥ 90% |
| 拒答 | 不可回答问题正确拒答率 | ≥ 90% |
| 性能 | 检索与重排 P95，不含最终 LLM 生成 | ≤ 5 秒 |
| 稳定性 | 百炼正常且配额充足时，5 并发应用错误率 | < 1% |

性能指标在服务器部署后复测。外部模型生成速度单独观测，不将第三方服务延迟包装为应用自身可保证的固定 SLA。

## 14. 测试设计

- **单元测试**：各格式解析、OCR 分支、父子切分、ID 和元数据、RRF、父块去重、配置校验、鉴权、CSRF 和重试策略。
- **集成测试**：使用真实 Qdrant 与 SQLite，外部模型默认使用确定性 Fake，覆盖上传、更新、删除、活动代切换和恢复。
- **OCR 测试**：使用带已知真值的扫描 PDF，验证页码、文本覆盖率和失败处理。
- **真实 API 冒烟测试**：仅在显式环境开关和 Key 存在时运行，验证模型 ID、Embedding 1024 维输出、流式响应、Rerank 结构及 LangSmith 连接。
- **端到端测试**：完整构建规定的 Mock 语料，验证问答、引用、反馈、会话和知识库管理。
- **故障测试**：超时、限流、Qdrant 停止、LangSmith 停止、损坏文件、OCR 失败、Worker 中断和索引恢复。
- **性能测试**：5 并发问答及批量导入，分别测量应用、检索、Rerank 和生成延迟。
- **安全测试**：未登录访问、会话过期、CSRF、非法文件、超大文件、路径穿越和密钥泄露检查。

本地无法执行的 Ubuntu 专属测试必须明确标记为未执行，并纳入服务器验证报告，不以 Mock 结果替代真实上线验收。

## 15. 部署隔离

默认目录为 `$HOME/enterprise-rag`：

```text
enterprise-rag/
├── app/
├── frontend/
├── configs/
├── mock_data/
├── tests/
├── scripts/
├── runtime/qdrant/
└── var/
    ├── raw_files/
    ├── qdrant/
    ├── bm25/
    ├── sqlite/
    ├── snapshots/
    └── logs/
```

部署约束：

- Conda 环境固定命名为 `langchain_test`，Python 3.11。
- 提供 `environment.yml` 和精确依赖锁定文件；安装脚本不使用未固定版本的最新依赖。
- Qdrant 使用固定版本的独立二进制，数据和日志均位于项目目录。
- Qdrant 默认监听 `127.0.0.1:16333` 和 `127.0.0.1:16334`。
- FastAPI 默认监听 `127.0.0.1:18000`。
- 三个进程分别为 Qdrant、FastAPI 和 ingestion Worker。
- 启停脚本只根据本项目 PID/服务名管理进程，不操作系统中其他服务。
- 提供独立 systemd 模板，由用户决定是否安装，不自动启用系统级服务。
- OCR 默认 CPU；GPU 仅作为可选加速，不修改系统 CUDA 或其他 Conda 环境。
- 提供独立 Nginx 配置示例，由用户手动决定是否接入；不自动修改现有 Nginx。
- 直接对外开放应用时必须配置 HTTPS；仅 HTTP 的监听方式限可信内网或本机验证。

## 16. 备份、恢复和卸载

### 16.1 备份

备份脚本暂停新写入并等待当前索引任务到达安全点，然后保存：

- SQLite 一致性备份。
- Qdrant 官方快照。
- 活动 BM25 目录和索引代记录。
- 原始文件及非敏感 YAML 配置。
- 备份 manifest、版本号和校验值。

`.env` 不进入备份包。备份完成后恢复正常服务，并记录失败而非静默跳过组件。

### 16.2 恢复

恢复到隔离目录，完成版本、文件校验、SQLite、Qdrant、BM25 和活动代一致性检查后，才允许切换服务。提供完整重建作为无法恢复索引时的最后手段。

### 16.3 卸载

停止脚本只停止本项目三个进程。删除数据和移除 `langchain_test` Conda 环境必须由用户分别确认，不提供无提示的强制删除。

## 17. 交付物和手动上线步骤

### 17.1 交付物

- 完整前后端源码和 RAG 链路。
- 百炼模型、Qdrant、BM25 和文档处理适配器。
- Mock 生成器、生成后的全部语料、1000 条知识 Q&A 和 100 条评测数据。
- 全部自动化测试、评测脚本和报告模板。
- Conda 环境文件、依赖锁文件、配置示例和 Qdrant 固定版本安装脚本。
- 初始化、启动、停止、健康检查、备份、恢复和验证脚本。
- 架构、配置、API、LangSmith、评测、部署和故障排查文档。

### 17.2 用户手动部署

1. 上传本地构建并验证过的压缩包。
2. 创建 `langchain_test` Conda 环境并安装锁定依赖。
3. 创建 `.env`，填写百炼和 LangSmith 配置。
4. 检查模型、检索和服务 YAML。
5. 安装项目专属 Qdrant，初始化 SQLite 和管理员。
6. 启动 Qdrant、API 和 Worker。
7. 导入 Mock 知识库并运行真实 API 冒烟测试。
8. 运行评测及部署验证脚本，查看本地报告和 LangSmith。
9. 按需配置反向代理、HTTPS 和 systemd。

部署验证脚本输出环境、依赖、端口、模型、索引、磁盘和 LangSmith 检查结果。任何失败项均阻止将部署标记为验收通过。

## 18. 完成边界

开发者负责本地开发、测试和交付部署材料，不直接操作服务器。只有在相应命令实际执行且输出满足验收条件后，才能声称测试通过或部署完成。服务器最终上线以用户手动执行后的验证报告为准；未执行的真实 API、OCR GPU、Ubuntu 或服务器测试必须如实标注。
